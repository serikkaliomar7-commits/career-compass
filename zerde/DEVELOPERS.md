# Зерде — для разработчиков

Сайт подготовки к вступительному экзамену БИЛ (Білім-инновация лицейі) для 5–7 классов.
Интерфейс на казахском (основной) и русском.

## Коротко об устройстве
- **Без фреймворков и без обязательной сборки.** Чистый JavaScript (ES5/ES2017) и общий объект `window.Z`.
  - Каждый файл в `js/` — самостоятельная IIFE. Порядок подключения задан в `index.html`, и он важен.
  - `index.html` работает и прямо с диска (`file://`), и с любого хостинга.
- **Задачи не хранятся готовыми, а генерируются.** Каждая задача создаётся генератором с детерминированным ГПСЧ (`Z.util.rng(seed)`): один seed — одна и та же задача. На этом держатся тетрадь ошибок, печать вариантов и «Практика».
- **Два режима бэкенда** с одинаковым интерфейсом (`js/backend.js`):
  - `demo` — аккаунты в `localStorage` этого браузера. Только для показа, продавать в нём нельзя.
  - `supabase` — боевой режим. Включается, если в `js/config.js` заданы `supabaseUrl` и `supabaseKey` (anon key). Деньги, доступ, промокоды, баллы и журнал решает сервер (`supabase/schema.sql`, RLS + функции `security definer`).

## Как добавить тип задачи
1. Положите формат в нужный `gen_*.js`: `F.<тема>.push({ id: 'bil.my_type', lv: [2, 3], f: function (r, lvl, opt) { … return Q(…); } })`.
2. Правила для формата:
   - вся случайность только из `r`;
   - всегда 4 разных варианта ответа и ровно один верный;
   - текст на казахском и на русском;
   - решение с шагами;
   - минус пишется как «−».
3. Если тип нужен в «Практике», укажите его id в слоте схемы (`js/practice.js`).
4. Тест проверит, что формат существует на этом уровне.

## Проверки
```bash
cd zerde
npm install          # один раз: esbuild для сборки
npm test             # tests/run.js (400 сидов по каждой теме, форматам, тестам, «Практике») + tests/backend.js
SEEDS=40 node tests/run.js   # быстрый прогон
```
- `tests/run.js` для каждой темы, уровня и сида проверяет:
  - нет `undefined`/`NaN`;
  - варианты ответа разные, верный ровно один;
  - разнообразие типов в домашке;
  - составы тестов;
  - воспроизводимость вариантов «Практики»;
  - схемы экзаменов.
- `tests/backend.js` проверяет демо-режим:
  - регистрацию и правила пароля;
  - PBKDF2 и блокировку подбора;
  - промокоды;
  - оплату;
  - баллы с лимитами;
  - родителя;
  - журнал и админ-обзор.
- GitHub Actions (`.github/workflows/zerde.yml`) запускает тесты и сборку на каждый push в `zerde/`.

## Сборка и публикация
- `npm run build` создаёт папку `dist/`:
  - один сжатый JS-файл (около 1,2 МБ, после gzip около 370 КБ) и сжатый CSS, оба с хешем в имени;
  - `index.html` и `404.html`;
  - заголовки безопасности, manifest, иконки.
- **Netlify:** Base directory `zerde`. Сборка и публикация уже описаны в `netlify.toml`, заголовки в `_headers`.
- **Vercel:** Root directory `zerde`, остальное в `vercel.json`.
- Локально: `npm run build && node tools/serve.js dist` → http://localhost:8080.

## Безопасность
- В коде лежит только **anon key** Supabase. **Ключ `service_role` в код и в репозиторий никогда не кладётся.**
- Права проверяет сервер:
  - RLS: каждый видит своё, родитель видит привязанного ребёнка, админ видит всё;
  - роль, доступ и оплату меняют только функции `security definer`;
  - журнал пишется только через `log_activity` (белый список видов, не больше 400 записей в день).
- Правила пароля:
  - не короче 8 символов, обязательно буквы и цифры, без частых паролей — так проверяет страница;
  - то же правило нужно включить в Supabase Auth, иначе его можно обойти.
- CSP и другие заголовки задаются в `_headers` и `vercel.json`. Новый внешний домен (CDN, аналитику) сначала добавьте в CSP.
- Персональные данные граждан РК по закону «О персональных данных и их защите» должны храниться в базе на территории РК. Перед продажей решите это с юристом (см. `ЗАПУСК.md`).

## Стиль кода
- Пишите в стиле соседнего кода: короткие функции, комментарии по-русски там, где неочевидно.
- Строки интерфейса не хардкодить, а добавлять в словари `kk` и `ru` (`js/i18n.js` или `L` в `js/views.js`).
- Для HTML используйте `esc()`, для дробей `fx()`/`U.mathFrac`.
- Исходные материалы экзаменов (PDF, DOCX) лежат в `materials/` и в git не попадают (`.gitignore`).
